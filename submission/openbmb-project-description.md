# OpenBMB 比赛项目说明

## 项目名称

浮伴 Floating Pet

## 一句话简介

浮伴是一只基于 MiniCPM-o 的 Windows 全模态桌面陪伴宠物：它默认安静地待在桌面上，在用户明确授权后理解语音、视觉和当前上下文，等重复线索被确认后再发起一次可拒绝的协助。

## 我们要解决的问题

桌面上的 AI 助手通常有两个极端：要么藏在用户想不起的入口里，要么持续弹窗和采集，把工作空间变成一个被打断的聊天窗口。真正有用的陪伴需要同时做到三件事：在场但不抢焦点，能理解正在发生的事情，介入时又不越过用户的边界。

浮伴把“看见”和“介入”拆成两个动作。用户可以先让它保持安静，再分别打开麦克风、摄像头或指定屏幕；当同一个问题再次出现，浮伴先询问是否需要一起看看，用户接受后才进入协助流程。

## 产品方案

### 1. 安静的桌面形态

浮伴使用 Electron 实现 Windows 透明置顶窗口，支持桌面拖拽、边缘吸附、托盘入口和键盘操作。它不占用任务栏主空间，状态通过宠物角标、Dock 和状态条表达。

### 2. 受控的多模态感知

麦克风、摄像头和指定屏幕是独立输入源，默认关闭。用户可以逐项开启、暂停或结束陪伴，输入轨道和实时连接会随状态及时停止。字幕可以在不播放语音的情况下提供反馈，Windows Demo 默认静音。

### 3. 有边界的主动协助

主动协助不是一次异常就弹窗，而是先记录线索，等重复问题被确认后再询问。接受后，浮伴打开协助卡，保留当前会话上下文，支持继续追问、任务拆解和下一步建议；拒绝或开启勿扰时不再打断。

### 4. 可持续的个人上下文

产品提供记忆查看、修改和删除，并支持在用户确认后持久化称呼、目标和偏好。同时提供任务、便签和专注计时，让一次对话能落到后续行动，而不是停在一句回答上。

## MiniCPM-o 的使用方式

项目将 Electron 客户端和 Python 模型适配服务分开，客户端只处理桌面交互、权限状态和用户控制，模型服务负责把输入转换成 MiniCPM-o 可处理的协议。

- 回合制 Chat 链路：文字输入，以及经校验的 JPEG 视觉帧和短 WAV 音频。
- Realtime 链路：16 kHz 音频输入、JPEG 视觉帧、增量文字事件和 24 kHz 音频输出。
- 服务不可用时：客户端进入明确的离线或 Fake 模式，不把固定演示回复描述成真实模型理解。

这种拆分让产品可以在本地先验证交互和隐私边界，也能在模型服务可用时替换成真实推理链路，不需要重写桌面产品。

## 技术结构

```text
Windows Electron
  ├─ 透明置顶桌宠、托盘、Dock、设置与状态机
  ├─ 任务、便签、记忆、专注计时的本地持久化
  └─ Preload 安全桥接
       ↓
Python 模型适配服务
  ├─ Chat：文字 / JPEG / WAV
  └─ Realtime：16 kHz 输入 / 增量文字 / 24 kHz 输出
       ↓
MiniCPM-o 模型服务
```

HarmonyOS NEXT PC 工程复用 Renderer，并通过 ArkTS 能力桥接系统侧能力，作为后续跨端路线；本次 OpenBMB 提交重点展示 Windows 产品本体和 MiniCPM-o 链路。

## 已完成与可验证内容

- Windows 透明置顶桌宠和托盘交互。
- 感知默认关闭，麦克风、摄像头、屏幕逐项授权。
- 主动询问、协助卡、连续追问和会话上下文。
- 记忆查看、修改、删除，以及确认后的称呼、目标、偏好持久化。
- 任务、便签和专注计时，专注计时支持重启后恢复剩余时间。
- Chat 和 Realtime 的客户端协议适配与边界校验。
- 离线 Fake Demo，可在没有模型服务时展示完整产品交互。
- `npm run check` 通过，单元测试 101 项通过。

## Demo 与宣传页

提交包包含：

- `floating-pet-promo.html`：单文件、可离线打开的宣传页，内嵌当前产品宠物形象和托盘 Logo。
- `../desktop/release/Floating-Pet-Demo-Portable-0.1.0-x64.exe`：Windows 便携 Demo。
- `../docs/demo-video-script.md`：宣传片脚本和录制边界。

运行离线 Demo：

```powershell
Set-Location .\desktop
npm ci
npm run start:fake
```

宣传页中的视频区域使用本地文件选择器播放，不依赖网络，也不会上传视频。HTML 与 `desktop/release/` 需要保持相对目录关系。

## 诚实的能力边界

Fake 模式中的重复错误、诊断文本和 Realtime 占位输出只用于验证 UI、状态机和协议闭环。它不代表模型已经理解任意屏幕，也不代表固定回复来自真实推理。需要展示模型效果时，应在已接通的服务环境中单独录制，并明确标注真实服务来源。

项目不随仓库分发模型权重、凭据、私钥、签名材料或构建缓存。评审可以先用离线 Demo 体验产品形态，再按 `desktop/README.md` 的说明配置模型服务进行真实链路验收。

## 项目价值

浮伴的重点不是把更多模型能力堆到桌面上，而是把多模态能力变成一种有分寸的陪伴：它能看见上下文，但不会默认采集；它能主动靠近，但必须先征得同意；它能记住被确认的信息，也允许用户随时查看、修改和删除。MiniCPM-o 在这里承担的是理解和表达，最终的产品体验由清晰的权限边界、可恢复的本地状态和可验证的交互闭环共同完成。
