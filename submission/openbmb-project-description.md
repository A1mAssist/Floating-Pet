# 浮伴 Floating Pet

## 项目简介

浮伴是一只住在 Windows 桌面上的全模态陪伴宠物。它平时安静地待在角落里，用户需要时再打开麦克风、摄像头或指定屏幕，让它一起看看眼前发生了什么。

我们想做的事情很具体。用户遇到报错、忘记下一步，或者手头的任务突然卡住时，不必重新整理一大段背景再去找助手。浮伴可以先保留当前会话，等相同线索再次出现后问一句是否需要帮助。用户点头，它才进入协助；用户拒绝，它就停在原地。

## 为什么做成桌宠

很多助手都在聊天窗口里等待输入。用户得先离开当前工作，再把问题搬进窗口。浮伴把入口放回桌面，但不占据桌面。它支持透明置顶、拖动、边缘吸附和托盘操作，状态通过宠物角标、Dock 和状态条表达。

这个形态带来一个很小但重要的变化。用户不用先决定“我要和 AI 对话”，只要继续做手头的事。浮伴在得到明确授权后，才把当前线索带进一次协助。

## MiniCPM-o 在项目里做什么

项目把桌面客户端和模型服务分开。Electron 负责窗口、输入权限、会话状态和本地数据，Python 服务负责把这些输入整理成 MiniCPM-o 能处理的请求。

回合制 Chat 支持文字，以及经过校验的 JPEG 视觉帧和短 WAV 音频。Realtime 链路支持 16 kHz 音频输入、JPEG 视觉帧、增量文字事件和 24 kHz 音频输出。模型返回的内容再回到桌面协助卡，用户可以继续追问，也可以随时停止。

这样的拆分让产品在没有模型服务时仍然能演示完整的桌面交互。模型服务恢复后，客户端不需要换一套产品流程。

## 产品体验

浮伴从“默认关闭”开始。麦克风、摄像头和屏幕输入各自有开关，暂停采集、勿扰和结束陪伴都会停止相应链路。语音可以关闭，字幕可以保留，Windows Demo 默认不会发出声音。

主动协助也有明确的门槛。第一次看到线索时，浮伴只做记录；同一个问题再次出现，它才把询问放到桌面上。协助卡打开后，当前对话会保留上下文，用户可以从定位原因继续问到下一步行动。

除了对话，产品还提供记忆、任务、便签和专注计时。记忆可以查看、修改和删除，称呼、目标与偏好只有在用户确认后才会持久化。专注计时会保存结束时间，应用重启后可以继续显示剩余时间。

## 技术结构

```text
Windows Electron 客户端
  桌宠窗口、托盘、Dock、设置、权限状态和本地数据
                ↓
Preload 安全桥接
                ↓
Python 模型适配服务
  Chat：文字、JPEG、WAV
  Realtime：16 kHz 输入、增量文字、24 kHz 输出
                ↓
MiniCPM-o 模型服务
```

HarmonyOS NEXT PC 工程复用了 Renderer，并通过 ArkTS 能力桥接系统侧能力。这条路线作为跨端延伸保留，本次比赛提交重点放在 Windows 产品本体和 MiniCPM-o 链路。

## 当前可以验证什么

评审可以直接运行离线 Demo，体验桌宠常驻、输入控制、主动询问、协助卡、记忆管理、任务、便签和专注计时。项目中的客户端检查和单元测试已经跑通，当前单元测试共 101 项。

接入模型服务后，可以继续验证文字 Chat、视觉帧、短音频，以及 Realtime 的音频和增量文字链路。服务不可用时，Demo 会保持明确的 Fake 或离线状态。

## Demo 运行方式

无需安装的在线 Web Demo：[https://floating-pet-web-demo.vercel.app/](https://floating-pet-web-demo.vercel.app/)

在线版本复用 Electron Renderer，可体验主动询问、Fake 对话、记忆、任务、便签和专注计时；数据只保存在当前浏览器。它固定静音，不请求麦克风、摄像头或屏幕权限，也不连接模型服务。

```powershell
Set-Location .\desktop
npm ci
npm run start:fake
```

提交包里还有一个单文件宣传页 `floating-pet-promo.html`。它可以离线打开，内嵌当前产品的宠物形象和托盘 Logo。宣传片随页面部署，也可以通过本地文件选择器临时替换，所选视频不会上传。Windows Demo 的下载入口使用相对路径，提交时请保留 `submission` 和 `desktop/release` 的目录关系。

## 能力边界

Fake 模式里的重复错误、诊断文字和 Realtime 占位输出，用来验证界面、状态机和协议闭环。它们不代表模型已经理解任意屏幕，也不代表固定回复来自真实推理。模型效果需要在真实服务环境中单独验收，并在录制或答辩时标注来源。

项目不把模型权重、凭据、私钥、签名材料和构建缓存放进源码仓库。这样评审拿到的每一项能力都有清楚的来源，也方便后续替换模型服务和继续迭代产品。

## 项目价值

浮伴关心的是多模态能力如何进入日常工作。模型负责理解声音、画面和文字，产品负责把它放在合适的距离上。用户愿意打开时，它能靠近；用户想安静工作时，它会停下；用户确认过的内容可以被记住，也可以被查看和删除。
