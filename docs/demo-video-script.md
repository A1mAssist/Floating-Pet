### 1.2 当前边界，不写成已完成功能

1. 手机 Web 控制面板、配对和远程控制尚未实现。本文只预留场外 cue，不在正片中展示手机。
2. `start:fake` 不做真实屏幕理解。重复错误由 Mock cue 注入，画面必须保留 `Fake` 标识，并出现一次“Mock 线索注入”字幕。
3. Fake Chat 是围绕 `task.steps` 的确定性场景，不代表从当前屏幕生成了诊断。
4. Fake Realtime 返回固定英文占位文字和静音 PCM，只能证明 UI/协议链路，不作为模型效果镜头。
5. 当前会话能保留上下文，但没有可宣传的长期记忆。
6. 当前 `release/0.1.0` 是旧包。录制必须运行当前源码构建，不能打开旧安装包。

## 2. 创意主线

**一句话故事：** 浮伴默认安静地待在桌面；用户按需开启感知后，它等到同一个问题被再次确认，先礼貌询问，再带着当前上下文一起解决，最后把控制权完整交还给用户。

**情绪节奏：** 安静存在 → 用户授权 → 注意到重复问题 → 温和询问 → 连续协助 → 主动退场。

**视觉原则：**

- 真实录制当前 Electron UI，不重绘假界面。
- 编辑器是主场景，桌宠始终在右下角；只有提示和协助卡出现时才推近桌宠。
- 手机控制面板完成后只作为场外 cue desk，不进入正片，避免观众误解为产品端能力。完成前，所有镜头都能通过当前 UI 手动执行。
- 保留应用内 `Fake` 徽标；Mock 触发镜头增加一次小号字幕“Mock 线索注入”。
- 音乐保持克制，重点动作只配玻璃轻触、提示音和消息到达音。

## 4. 旁白整稿

> 卡住时，麻烦的不只是报错，还有重新解释上下文。
>
> 浮伴常驻桌面。只有你主动开始，它才进入陪伴状态。
>
> 麦克风、摄像头和指定屏幕，都由你逐项开启。主动程度、勿扰、演示模式、语音和字幕，也能独立控制。
>
> 这段 Demo 注入一组重复错误线索。第一次，它只记录；再次确认后，才决定询问。
>
> 它不会直接打断，更不会替你做决定。它先问一句：需要我一起看看吗？
>
> 同意后，浮伴把当前 Mock 场景变成一轮可以继续追问的协助。它先定位边界问题，再记住这一轮正在解决什么。
>
> 麦克风开启后，也可以显式启动或停止实时输入链路。
>
> 不想被打扰，一键勿扰。需要收回权限，暂停采集会立即停止所有输入。
>
> 真实服务已在昇腾 910B2 完成验证。需要时出现，完成后安静退场。浮伴。

## 5. 手机 Web 控制面板 cue 清单

以下是后续控制面板需要支持的最小拍摄动作，不代表当前已经存在对应 API。控制面板完成前，操作者按表中目标使用当前 UI；完成后，控制面板只在镜头外使用。

| Cue | 目标状态 | 录制注意 |
|---|---|---|
| `RESET` | 幂等回到感知关闭、无输入、无面板的拍摄初始状态 | 空闲时不得反向开始会话；结束会话不会重置主动程度、语音、字幕、屏幕来源和窗口位置，控制器需显式恢复拍摄预设 |
| `SESSION_START` | 开始陪伴，输入仍关闭 | 保留 Dock 和状态 Bar 的变化 |
| `OPEN_SETTINGS` | 打开设置面板 | 不自动滚动，镜头需要先拍顶部隐私说明 |
| `INPUT_PRESET_DEMO` | 麦克风开启、摄像头预览出现后关闭、编辑器窗口屏幕开启 | 串行等待来源列表加载、麦克风 live、摄像头预览、摄像头停止、屏幕 live；最终角标必须为 `2` |
| `CLOSE_SETTINGS` | 回到桌宠主画面 | 确认宠物角标为 `2` |
| `MOCK_REPEAT_ERROR` | 复用 Dock 模拟按钮的 `simulateCueFlow()` 入口；注入第一条线索，并由现有逻辑约 5.1 秒后自动补第二条 | 不得只调用单次 `emitCue()`；平衡模式、勿扰关闭、演示模式关闭 |
| `ASSIST_ACCEPT` | 接受询问并打开协助卡 | 气泡至少停留 1 秒再触发 |
| `MESSAGE_PRESET_1` | 发送“steps 为什么报错” | 等回复完整显示后再进入下一 cue |
| `MESSAGE_PRESET_2` | 发送“那下一步呢” | 展示上下文回复后停留 1.5 秒 |
| `REALTIME_ON` | 开启实时链路并显示“实时监听中” | 构图裁掉对话区，成片静音 |
| `REALTIME_OFF` | 状态稳定约 0.6 秒后停止实时链路 | 必须早于首个约 1 秒音频块，确认状态恢复“麦克风已就绪” |
| `DND_ON` / `DND_OFF` | 开启或解除勿扰 | 每个状态至少停留 1 秒 |
| `CAPTURE_PAUSE` | 停止全部媒体输入 | 确认 Toast 为“采集已暂停”、角标归零、状态为“陪伴中 · 输入关闭” |
| `SESSION_END` | 幂等结束陪伴并回到“感知关闭” | 暂停采集后至少等待 2.1 秒让 Toast 消失；空闲时保持空闲，不得实现为简单 toggle |

## 6. 录制准备

1. 使用当前源码运行 `npm run start:fake`，不要打开旧 `release/0.1.0`。
2. 使用 OBS“显示器采集”。Electron 硬件透明层在 GDI 窗口捕获中可能缺失。
3. 录制前关闭通知、个人账号信息和系统弹窗，准备无隐私内容的本地编辑器 fixture。
4. 提前授予麦克风、摄像头和屏幕权限；预热一次来源列表和摄像头，再停止输入并保留编辑器来源选择。
5. 第一次 `SESSION_START` 前设置为“平衡”，关闭勿扰、演示模式和应用系统语音，保留字幕；若用重启执行 `RESET`，必须重新应用这些设置。旁白统一后期录制。
6. Fake Realtime 的音频轨静音。真实模型效果如需入片，必须单独录制真实服务镜头并明确标注，不能套用 Mock 画面。
7. 每个段落至少录制三遍：一次完整操作、一次 UI 近景、一次无鼠标停留，方便后期切镜。
8. 每次重录主动询问前先执行 `SESSION_END` 再重新开始，避免已处理事件和冷却状态影响结果。

## 7. 交付前事实审查

1. **Mock 被剪成真实屏幕识别：** 保留 `Fake` 徽标，并在注入镜头显示“Mock 线索注入”。
2. **Fake Realtime 被误解为模型语音效果：** 只展示开始/停止状态，静音且不展示固定回复。
3. **确定性诊断被说成任意场景理解：** 旁白明确称为“当前 Mock 场景”。
4. **手机控制被误解为产品功能：** 手机不入正片，控制面板仅作为场外拍摄工具。
5. **旧安装包与当前源码混用：** 录制前核对 Dock 为 Liquid Glass、状态 Bar 有 `Fake` 徽标，并从当前源码启动。
